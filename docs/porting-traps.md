# Porting traps and lessons

Numbered lessons from bugs found while porting `@dotenvx/dotenvx` v2.38.2. Each says what goes wrong and how to avoid it. [CONTRIBUTING.md](../CONTRIBUTING.md) and source comments refer to them by number (`#NN`); keep numbers stable and append new traps at the end. Numbers 1-16 concern the parity test suite; the rest continue in one sequence.

## Pin notes

- The submodule is pinned to the exact `v2.38.2` tag. Native OS secret storage is the default for `encrypt`/`set` when it is enabled and `CI` is unset, so parity tests pass `--no-native --no-armor` (or `DOTENVX_NO_NATIVE=true`) to keep the real OS store untouched.
- `precommit`/`prebuild`/`gitignore` are deprecated at the pin in favor of `dotenvx protect`; they still run and print the deprecation warning.

## Parity test suite

1. **Test and implement only what the pinned commit supports.** A flag or variable that exists only in later upstream commits (`--file`/`DOTENV_FILE` were one such case and were removed) makes Node fail with "unknown option" and makes the port differ from the target. Check `dotenvx --help` at the pin before using a flag seen in upstream's changelog.
2. **Fresh keypairs are not deterministic.** `resolvers/keypair.js` looks up a private key through an already-present `DOTENV_PUBLIC_KEY` in the `.env`; it never derives one from a loose `.env.keys`. Use the shared fixed fixture (`FixedKeypairFixture`) for deterministic keys. Round trips that reuse an existing keypair (one CLI encrypts, the other decrypts) are stable.
3. **Fresh key generation needs `--no-native --no-armor` on Node.** Without them Node routes through the native store and may write no `.env.keys` at all. Any `set`/`encrypt` scenario whose `.env` lacks a `DOTENV_PUBLIC_KEY` hits this. Add the flags to the Node call only, never to the shared arguments of `RunBothAsync` (the .NET CLI rejects them there), and check new scenarios for it up front.
4. **`npm`/`npx` are `.cmd` files on Windows.** `Process.Start` without a shell does not resolve them; `NodeParityFixture` resolves them with a PATH/PATHEXT-aware lookup.
5. **Compare stdout and exit code, not stderr wording**, unless a scenario is about stderr. Two stream-routing bugs surfaced this way: `Console.Out/Error` defaulted to `\r\n` on Windows (Node always writes `\n`), and only `info` may go to stdout (`error`, `warn`, `success`, `help`, `verbose`, `debug` go to stderr). `ls`'s summary line is on stderr and includes elapsed time, so it is excluded.
6. **`ls` was never run end to end until late.** Its default pattern list was empty (listing nothing) and patterns needed the `**/` prefix to match nested files. Reading code is not the same as running it against the reference CLI.
7. **Global options (`-l -q -v -d`) must be `Recursive`.** Otherwise System.CommandLine only recognizes them before the subcommand name, and `get -v` became a key named `-v`. `GlobalOptionsParityTest` pins this.
8. **`WriteIndented` JSON uses `Environment.NewLine`.** Node's `JSON.stringify` always emits `\n`; set `NewLine = "\n"` (and see #62 for escaping).
9. **`Picomatch(null)` matches nothing.** Callers must guard with `keys?.Length > 0` before consulting the predicate. See #28 for the variant with a non-empty ignore list.
10. **Do not byte-diff output that contains the whole process environment** (`get --all`); each runtime injects its own variables. Compare a distinctive marker variable instead.
11. **`set`'s default for a missing file is the empty string, not `encrypt`'s sample kit.** Check each command's own transform before reusing a fix from a similarly named sibling.
12. **Constructor changes break mocks at run time, not compile time.** `Substitute.For<T>(ctorArgs...)` needs an exact argument count (default values do not apply), and `T.Factory = ...` lambdas are a separate set of call sites. Grep both after changing a constructor.
13. **`decrypt --mask` only affects `--stdout` output**, and it masks every key, `DOTENV_PUBLIC_KEY` included.
14. **`decrypt` keeps going after a failed key.** One undecryptable value does not abort the file, and `error` and `changed` are independent, so a file can both log `DECRYPTION_FAILED` and report "decrypted". The per-key message is always the generic `could not decrypt {key}`, unlike `run`/`get`/`set`, which surface the specific cause. Do not "fix" `decrypt` toward the others.
15. **A command's single-KEY branch must honor `--format`.** `keypair KEY --format colon` prints `KEY:value`; the single-result branch had ignored the format.
16. **System.CommandLine `Option<T[]?>` is an empty array, not null, when omitted.** `GetValue(opt) ?? default` never applies; test `Length > 0`.

## Everything else

17. **`Command.Hidden` cannot hide a command from one parent's listing only.** `HelpBuilder.Write` returns early for a hidden command, so `ext --help` printed nothing. `--help` is now rendered from the generated spec (see #74), which also solves the listing.
18. **A service's own default and its CLI action's default can differ** (`Prebuild` defaults the directory to `./`, the action to `.`). Write at least one test that constructs the service with no arguments.
19. **`precommit`'s staged-file check silently skips nested files on Windows.** `path.join` yields backslashes while `git diff --name-only -z` prints forward slashes. This is upstream's real behavior and is reproduced, not fixed.
20. **`sealed()` requires every occurrence of a duplicated key to be encrypted.** `DotenvParse`'s last-wins and its `collectAllValues` parameter (which keeps the first) cannot express that; `Sealed` has its own parsing.
21. **The CLI project has no `InternalsVisibleTo`.** A test seam for CLI-only logic must live in `Dotenvx.Core`, following the delegate-swap convention.
22. **Directory arguments for `-f`.** `run`/`get`/`validate` resolve a directory passed to `-f`/positional arguments through `buildCommandEnvs`/`resolveDirectoryFilepath` (`./config` becomes `./config/.env`, with `--convention` each convention file under it). `validate` deliberately does not fall back to `DOTENV_FILE`/`DOTENV_PATH`. `NodePathJoin` must do full lexical normalization like `path.join`, not just collapse `.`. When one action lacks a shared helper, grep every other caller of that helper.
23. **Compute a shared fallback once.** `determine()` reuses one `defaults` value in two branches; porting it per branch gave `run --env "FOO=bar"` the plain `.env` default while a `DOTENV_PRIVATE_KEY_PRODUCTION` was set.
24. **Verify output with a byte diff, not by eye.** A terminal read passed output that lacked the non-TTY color downgrade (`colorDepth.js`'s first line), the symbol prefixes, the real success color, and used a fabricated `[dotenvx@version]` success format. Pipe both outputs to files and compare bytes.
25. **A systematic stdout+stderr sweep finds what unit tests do not.** It found wrong success symbols and pluralization, invented hint lines, a missing-file `keypair` that exited 0, specific `WRONG_PRIVATE_KEY` codes that Node cannot produce through the shared resolver (primitives' `parse()` coarsens every decrypt failure to `DECRYPTION_FAILED`; only `main.js`'s standalone `parse()` function keeps the specific codes), and a missing `ls` summary line.
26. **A shared helper can have callers with opposite error needs.** `Services.KeyPair` backs the `keypair` command (which must fail on a missing `.env`) and the internal key lookups (which need a quiet null). Put the check in the command's action, not the shared class. Grep callers before adding validation to a helper.
27. **Check the submodule's git history, not just the worktree, before deciding no upstream source exists.** (This is how historical ports of removed commands were audited; `rotate` has since been removed from the port because it is not part of v2.24.1.)
28. **`Picomatch(null, nonEmptyIgnore)` is not "match everything".** Only a null include list with an empty ignore list is. With a non-empty ignore list the include predicate matches nothing, which silently skipped every key. Apply include filters only when `--key` was given.
29. **A live test can "prove" unreachability by testing the wrong scenario.** `FILE_NOT_WRITABLE` looked unreachable via an unwritable existing file (the read fails first and is swallowed); a brand-new file in a directory that denies creation shows the translation works. `Fsx.WriteFileX` maps `UnauthorizedAccessException` (EACCES/EPERM only; sharing violations are untouched).
30. **Single-flag sweeps and flag-combination sweeps find different bugs.** `-f ".env,.env.prod"` is split on commas by `collectEnvs` for `run/get/set/del/encrypt/decrypt/validate` (`SplitCommaSeparatedEnvFiles`), but not for `ls`/`genexample`/`ext *`, which use plain variadic options.
31. **`run --redact`, `--mask` and `--validate`.** `--redact` redacts by value (excluding `_PLAIN` keys) and filters the child's stdout/stderr only; the child's environment still holds real values. `--mask` masks a copy of the child's environment but not the validation environment. `--redact` uses a pseudo-terminal when all three standard streams are terminals (see #73).
32. **A non-zero child exit prints nothing extra.** A fabricated "Command exited with exit code N" line had been logged; Node suppresses its own message for `COMMAND_EXITED_WITH_CODE`.
33. **Unresolvable child commands.** See #72: Windows Node runs an unresolved command through `cmd.exe`, and the port reproduces that; elsewhere a missing command prints `Unknown command: X`.
34. **Rule out the harness before calling a sweep difference a bug.** A `precommit` scenario in a git repository with no commits made git itself fail; Node leaked git's stderr, the port suppresses it. Reproduce by hand in a realistic setup first.
35. **`keypair` merges several `-f` files.** The loop lives in the action, not in the shared `KeyPair` class (see #26), and a missing file aborts with that file's error.
36. **`AllowMultipleArgumentsPerToken` is false by default.** Genuinely variadic upstream options (`<name...>`) captured one value per occurrence and let the next token leak into a positional (`ls -f a b` crashed). Enable it only where upstream's registration is really `<name...>`: `-e`, `--ignore`, `-ik`, `-ek`, `-k`, `ls -f/-ef`, `genexample -f`, `--pattern`. `-f`/`-fk` elsewhere are singular per occurrence, and making them greedy would be a new divergence.
37. **A boolean default of true may have no off state.** `set -c/--encrypt` has no negation upstream; only `--plain` disables encryption, so `-c` can never override it.
38. **commander drops extra positionals but rejects unknown options; System.CommandLine does the opposite.** Resolved in #72 (lenient positionals plus an explicit unknown-option check).
39. **Greedy variadic options swallow unrecognized flags.** A `CustomParser` (`OptionParsers.ParseMultiValue`) rejects dash-leading values; it receives tokens after the framework's grouping, so it can reject but not regroup.
40. **`utf16le` encoding.** `DetectEncoding` returns the Node name `utf16le`; `Fsx.ReadFileX` must map it. Producers and consumers of an encoding name drift independently.
41. **Preserve a leading BOM like Node.** Node's raw decode keeps U+FEFF; `File.ReadAllText` strips it, so `Fsx.ReadFileX` decodes bytes with `GetString`. JS `\s` matches U+FEFF, .NET's does not, so every line-start `\s*` in the ported parsers also accepts U+FEFF. Verify both the write-back and the plain-parse ends of such a change.
42. **`--version`/`-V` must be recursive** like the other global options. The version string tracks the pinned tag.
43. **`\w` is ASCII-only in JS, Unicode-aware in .NET.** Use `RegexOptions.ECMAScript` for key-matching patterns (it does not fix `\s`; keep the U+FEFF alternative from #41). Patterns that match one known escaped key do not need it.
44. **Pass `keys` through.** `decrypt -k KEY` in file mode passed `null` for the key list and decrypted every key; only the `--stdout` branch was right.
45. **`run <command>` without `--` works upstream** through `inferCommandArgsFromProcessArgv`: skip `-f/--env-file` and its value and any dash-leading arguments, then take the first plain token onward. A port had rejected it, and its unit tests asserted the opposite of the real upstream tests because they were written from the test names. Read what upstream tests actually assert.
46. **`set KEY` with no value.** On a non-TTY stdin it throws `MISSING_VALUE`; on a TTY it prompts for a hidden value.
47. **`keypair KEY` for a present key whose value is null prints `null` and exits 0.** Distinguish "absent" from "null" (`TryGetValue`).
48. **`ls` never descends into `node_modules`, `.git` or bundle directories** (`.app .key .numbers .pages .photoslibrary`); prune during the crawl, not by filtering afterwards.
49. **Dead upstream code stays dead.** `unchangedFilepaths` was never populated in the historical `rotate`; the port reproduced that rather than "completing" it.
50. **`upsert` updates every occurrence of a duplicate key**, each keeping its own quote style.
51. **`_PLAIN` keys are never encrypted** by `set` or `encrypt`, and `set` reports "no change" when the new value equals the current one (no forced re-encryption).
52. **The library API (`Main.cs`) is a second implementation of the CLI logic and drifts independently.** Keep message formatting (`MessageWithHelp ?? Message`), `buildConfigEnvs`, convention/ignore normalization, `mask`, and the success messages in sync, and merge multi-key decrypt failures into one combined error (`could not decrypt FOO, BAR`). `ConfigOptions.Clone` preserves the runtime type.
53. **Keep `-e` and `-f` in command-line order.** Both feed one shared list; with `--overload` the later item wins, otherwise the first. `EnvItemOrdering` walks the raw tokens (see #72 for the arities).
54. **A deterministic structural test beats repeated manual sweeps.** `HelpTextParityTest` compares each command's options and descriptions and found missing aliases (`get --pp`), missing `(default: ...)` suffixes and paraphrased descriptions. It runs the .NET CLI with `DOTENVX_NATIVE_HELP=1` to read the real option definitions. `--pp` cannot appear in System.CommandLine's own help (only the first two aliases render).
55. **Reference comments go stale.** Several helpers named upstream files that moved into `@dotenvx/primitives`. Sweep them: check that each `Reference source:` file exists at the pin. This found a base64 decode before the missing-key check, a missing `Key` on `DecryptionFailedException`, and a public-key lookup that consulted `process.env` first (upstream reads only the file).
56. **`INVALID_CONVENTION`** is a real `errors.js` error. `run`/`validate` catch and log it; `get` calls the helper before its `try` block, so a bad convention crashes with a raw stack trace there. Match each command.
57. **`ErrorMessageParityTest`** compares every `DotenvxException` against `errors.js`. Its first run exposed a fixture bug: `NodeParityFixture` decoded subprocess output with the console code page. A harness that compares two captured strings can hide an encoding bug that affects both equally.
58. **Test merged stdout/stderr with a fake binary.** `GitleaksHelper` shells through `2>&1` so the kernel merges the streams (two async readers cannot keep order). `test/FakeGitleaks` stands in for the real tool. Do not pass an already-quoted command as one `ArgumentList` entry to `cmd /c`; write it to a temp script instead.
59. **`Picomatch` must default to `dot: false`.** A wildcard never matches a leading `.` unless `dot` is true or the pattern itself starts with `.`; only `ls` passes `dot: true`. Verify hand-written ports of npm packages against the real package.
60. **`IgnoreRule` regexes.** Verified against the real `ignore` package: basename patterns match nested content; `build/` does not match bare `build`; anchored patterns match nested content; `dir/**` needs the literal slash; character classes are supported.
61. **Small helpers.** `ResolveHome` must keep `~/foo` under home (`Path.Combine` drops home when the remainder is rooted); `NodePathJoin` concatenates then normalizes; `optional` needs ECMAScript regex mode; use `ToLowerInvariant`. `NormalizeDotenvConfigPath` reads `DOTENV_PATH || DOTENV_F` only.
62. **Match `JSON.stringify` escaping.** JS escapes only quotes, backslashes, control characters and lone surrogates; System.Text.Json escapes `&<>+'` and non-ASCII. Use `Helpers.JsonStringify` for every JSON that is printed.
63. **`\'` is unescaped to `'` inside single-quoted values** (and nothing else), in both parsers.
64. **`ls` file order differs from Node** (Fdir's filesystem-dependent order vs an ordinal sort); an accepted limitation.
65. **`Primitives.Scan` is the single line parser.** `Dotenvx.Primitives/Parse.cs` is the flat `parse`/`scan` implementation; `Core/Helpers/Parse.cs` is the `parseSync` engine on top. `PrimitivesOracleParityTest` compares them with the real package over an input table; add a row for every parser edge case.
66. **JS and .NET differ in these.** `\s` includes U+FEFF, U+00A0 and Unicode spaces (ECMAScript-mode .NET `\s` is ASCII); `trim` strips U+FEFF; multiline `^ $ .` treat CR, LF, U+2028 and U+2029 as terminators; `String.replace(str, str)` replaces the first occurrence and expands `$&` patterns; `split(null)` splits on "null"; `||` treats the empty string as falsy.
67. **Expand operators.** `:-` uses empty as unset, `-` uses has-key; `:+` uses non-empty, `+` uses has-key; no operator is `env[k] || ""`.
68. **`remove`, `upsert`, `sealed`, `publickeys`.** `remove` is line-based and follows open quotes across lines; `upsert` replaces every occurrence via placeholders; `sealed` needs all values encrypted except `DOTENV_PUBLIC_KEY*` and `*_PLAIN`; `publickeys` keeps the last value per key in first-appearance order.
69. **Source-editing hazard.** Some editors and shell heredocs rewrite backslash escapes. In C#, use `(char)92`-style constants for tricky characters, token substitution in test tables, and never type a raw U+2028 (it is a line terminator).
70. **Every `@dotenvx/primitives` export has a public `Primitives.*` counterpart.** The package ships no tests, so `PrimitivesOracleParityTest` and `PrimitivesExportsOracleParityTest` (about 2 minutes; do not wrap in a short timeout) compare against the real package and replay its README examples. `Keyring` with `Fk: []` disables file reads (null means `.env.keys`).
71. **Route through the primitives instead of re-implementing them.** Core's own parse engine, key lookup and encrypt/set/decrypt logic had hidden divergences; they are now 1:1 ports of `resolvers/envs.js`, `resolvers/keypair.js`, `transforms/{encrypt,decrypt,set}.js` and `main.js` `parse`. Effects: the default keys file is `.env.keys` in the working directory; the generated header carries `# -fk <path>` when it differs; `decrypt` upserts every value (escapes become real newlines); the public key is `publickeys(src)[0]`; `set` compares against the decrypted current value.
72. **Behavior that reversed earlier decisions.**
    - Windows `cmd.exe` fallback: when `which` cannot resolve a command, upstream re-runs it through `%COMSPEC% /d /s /c "..."`, so builtins work and a missing command shows cmd's own "is not recognized" text. `ExecuteCommand.ApplyComSpecFallback` reproduces it (use `Arguments`, not `ArgumentList`). On POSIX a missing command is `Unknown command: X`.
    - Unknown options are rejected with lenient extra positionals: every subcommand has `TreatUnmatchedTokensAsErrors = false` and `UnknownOptionGuard` reports dash-leading arguments before `--` as `error: unknown option`. A validator cannot do this because `--` is not in `CommandResult.Tokens`.
    - `-f` takes one value per occurrence, `-e` is variadic.
    - `-fk` is multi-valued and directory-aware where upstream is (`run/get/validate/decrypt/keypair`), single for `set/encrypt/del`.
    - `ignore` matches error codes exactly, `ConfigOptions.Envs`/`PathString` exist, and `ls -q` suppresses the summary.
    - Every upstream test title is cited by a `Refer to "<title>"` remark (intentionally not ported ones are skipped tests with the reason, inline in the related test file); `node scripts/upstream-test-titles.js` lists gaps.
73. **Lessons from Armor, native stores, lock, secret managers, spinner and dynamic dispatch**, found by comparing against Node with fakes (`FakeSecretCli`, `FakeArmorServer`):
    - `armor pull` reports `changed` from the `.env.keys` upsert, `armor down` from the API's flag.
    - enquirer drains stdin per prompt: two keystroke bundles written together are consumed by the first prompt and the second sees end of input (exit 0). `Prompts` mirrors that.
    - undici sends `Content-Type: application/json` even on a body-less GET; `getAccount` sends `Bearer undefined` for a missing token, other calls `Bearer `.
    - `conf@10` salts pbkdf2 with `iv.toString()` (UTF-8-decoded random bytes); the port reproduces it. The session file is a plain `.env` written by `jsonToEnv`.
    - `ApiException` is a `DotenvxException`; `messageWithHelp` exists only when the API sent `help`.
    - libuv finds executables as `.exe`/`.com` only on Windows, cwd first, then PATH; a `.cmd` shim named `op`/`bw`/`dotenvx-*` is "not installed" (`SecretCli.ResolveExecutable`).
    - `dotenvx-<cmd>` dispatch builds the child PATH as `<cwd>/node_modules/.bin:<PATH>` with a literal colon, and a missing program exits 0.
    - Native providers are on by default (supported platform, no `CI`, no `--no-native`) and are consulted for every missing private key; tests use a substitute store.
    - `update` prints the npm commands unless `process.pkg`; `doctor`'s exclude globs only match POSIX separators, so nothing is excluded on Windows (reproduced).
    - Real Windows Credential Manager writes can fail when the store holds about 650 entries (`cmdkey: Not enough memory resources`); clean up test credentials.
74. **`--help` is a data plus algorithm port.** System.CommandLine cannot print commander's layout (#17). `scripts/gen-help-spec.js` dumps what commander computes per command (usage, description, rows, `padWidth`) into `src/Dotenvx/Help/help-spec.json`; `CommanderHelp.cs` ports `formatHelp`/`wrap` and the root/`ext` overrides. The script captures the program by replacing the cached `executeDynamic` module (patching `Command` on the prototype does not reach the instance). `padWidth` includes ancestors' options, so it is stored, not recomputed; upstream's `enc`/`dec` are separate commands named as typed, so the path comes from the typed token and `help enc` must match aliases; JS `$`, `\s` and `trimEnd` differ from .NET. `HelpExactParityTest` compares every command path byte for byte, and `HelpSpecIsUpToDate` fails when the spec is stale.
75. **commander parses level by level; System.CommandLine does not.** Normalized in `Help/CommanderArgs.cs`, `Help/CommanderErrors.cs` and `HostExtensions`: (a) a required option value is taken whatever it looks like (`get -f --overload`) unless a level above claims it (`get -f -q` is `error: option '-f, --env-file <path>' argument missing`); (b) `-f=.env` and `-f:x` keep the separator in the value; (c) `--long:value` is an unknown option; (d) unknown options carry `(Did you mean --env?)` from `suggestSimilar`; (e) `-h/--help/-V/--version` win over an unknown command, and `-l get HELLO` makes `get` the level value; (f) `get ""` and `keypair ""` mean all keys; (g) do not feed program arguments to the .NET host configuration provider; (h) no extra help aliases (`-?`, `/?`); (i) a Windows-invalid path such as `:.env` reports a missing file. Accepted: a dash-leading value for a variadic option (`run -e --x`) cannot be passed through System.CommandLine; the node binary itself consumes `--env-file` anywhere in its arguments (the sweep spells it `-f` for Node); OS and runtime error wording stays native to .NET.
76. **Anything beyond the pinned version is a divergence, even when it looks useful.** `--file` and `DOTENV_FILE` came from a later upstream commit; they were removed so `dotenvx --help` and environment handling match v2.24.1 exactly (see #1).
77. **Small findings from the file-syntax, environment-variable and file-argument sweeps.** A missing parent directory is Node's ENOENT, so `Fsx.ReadFileSync` reports it as a missing file (an existing directory keeps the native error). `-f " "` and `-f ,` mean "no files" for `keypair` (`{}`), not the `.env` default. `ls " "` is a blank directory name, not an error (`path.resolve` semantics). Commander removes a known boolean root flag from the start of a cluster, so `set KEY -dash` is `-d` plus the value `-ash`. All fifteen `.env` syntax fixtures (comments, multiline, escapes, interpolation, Unicode, BOM and CR line ends, duplicates, 5000-character values) matched Node on every command that reads a file.
78. **Multi-step and cross-implementation sweeps.** The sweep can run a scenario as steps (`addSteps`), where each step names the CLI that runs it, so one implementation can write what the other reads. Encrypt, set and delete flows across 13 fixtures, 15 env file names (`.env.production`, `.env.staging.local`, `config/.env`, ...) and both directions matched Node, so ciphertext, key files and key names are interchangeable. Findings: `ls` orders names case-insensitively like Node's crawl on Windows; the `cmd.exe` fallback normalizes the command like cross-spawn (`path.normalize`: `""` becomes `.`, `./x` becomes `x`) because `/` is a switch character to cmd. Accepted: a trailing dot in an env file name (`.env.`) is stripped by Windows when .NET creates the file; masked random public keys differ per run.
79. **Git, lock and armor-settings sweeps.** The sweep can run `git` steps (the `.git` directory is not compared, except the installed `pre-commit` hook) and pipe a passphrase to a step's stdin. `precommit`, `prebuild` and `precommit --install` matched Node across 6 fixtures and 7 ignore-file variants, staged, unstaged, committed and outside a repository. `lock up/down` payloads are random, so `locked:<key>:<payload>` is normalized before comparing, and every passphrase shape (Unicode, spaces, 500 characters, CRLF, no newline, empty, extra lines) unlocked in both directions across implementations. Accepted: the passphrase prompt's redraw text on stderr, the random device key printed by `armor settings device`, and a tab typed into a piped passphrase (enquirer's key handling is not reproduced).
80. **Root options without a command, and `ls` crawl edge cases.** `dotenvx -q` (root options only, no command) prints the help and exits 1 exactly like no arguments; System.CommandLine added "Required command was not provided." on stderr (`HostExtensions`). `ls ''` crawls the current directory (a blank argument is `./`). Fdir skips directories it cannot read, so both the crawl and the summary's directory count use `IgnoreInaccessible`. Sweep scenarios must not point at the shared parent temp directory (`..`): it differs between the two runs.
81. **External programs are vetted through fakes on PATH.** `test/fakes/gitleaks.cs` stands in for `gitleaks` in the sweep (scenario env `FAKEGL_*` scripts its exit code and output, and its argument log is compared as a pseudo file), so `ext scan` is compared against Node without installing anything. It found that a failed `gitleaks detect` with no output still logs an empty error line (`error.stdout` is a Buffer, truthy even when empty).
82. **The OS secret stores, `op` and `bw` are vetted through the same fake in the sweep.** A scenario that sets `FAKECLI_SEED` (JSON of vault files) gets `test/fakes/secretcli.cs` copied as `op`, `bw`, `powershell` and `secret-tool` on PATH and a per-run vault directory whose files and call log are compared like output files (build the fake project first). Native scenarios set `CI` empty and do not pass `--no-native`. `native down` prints a shortened freshly generated public key, which the normalizer masks.
83. **macOS Keychain is vetted by redirecting the absolute binary.** `/usr/bin/security` cannot be shadowed on PATH, so `MacosKeychainParityTest` runs one get/set/delete sequence through upstream's `macosKeychain.js` (with `child_process.execFileSync` redirected) and through `NativeStore.MacosKeychain` (with `SecretCli.Exec` redirected) against the fake `security` in `test/fakes/security.cs`, and compares the results and the fake's call log. It runs on every platform. The end-to-end `native` flows are provider-agnostic and are swept with the Windows and Linux fakes.
84. **Pairwise and random-sequence sweeps.** Round 11 generates every pair of options for `get`, `set`, `del`, `encrypt`, `decrypt`, `keypair` and `run` from the help spec; round 12 runs 450 seeded random operation sequences (the seed is fixed, so every run is the same). The normalizer masks what is random or launcher-specific: the per-run directory name (also JSON-escaped inside a dumped environment), the `_` variable the shell sets to the launching program, and a masked random public key. A diff report now starts its window just before the first difference.
85. **An unknown first argument is the extension, whatever follows it.** `dotenvx foo get` runs `dotenvx-foo get`: commander's root `[command] [args...]` takes everything after the unknown command, but System.CommandLine matched the later `get` as a subcommand. `CommanderArgs.Normalize` reports the first root-level argument that is not a command (unless an unknown option came first, which stays commander's `unknown option` error) and `HostExtensions` dispatches before parsing. The sweep fakes extensions with `test/fakes/extension.cs` copied as `dotenvx-<name>`; the fake directory must not be the first PATH entry because upstream joins that entry with a literal colon (#73). The CLI's `setting log level to: <level>` debug line matches upstream's wording.
86. **The fakes are single-file apps in `test/fakes/*.cs`** (`secretcli`: `op`, `bw`, `powershell`, `secret-tool`; `security`; `extension`: `dotenvx-<name>`; `gitleaks`), with no project files. The sweep publishes one on first use (`dotnet publish test/fakes/<name>.cs`) and copies its apphost under each tool name; `Dotenvx.ParityTest` publishes all of them into `fakes/<name>/` next to the test assembly after a build (an incremental MSBuild target). Every file needs `#:property PublishAot=false`, because a file-based publish defaults to NativeAOT in .NET 10, which needs the C++ build tools.
87. **A value attached to a variadic option ends its values; NUL ends an environment value; Node's regex has a size limit.** Commander treats `-f=x`, `-fx` (also the `-fk` that is not an option of `genexample`) and `--env-file=x` as the option's complete value list, so the plain arguments after it are positional (`genexample -fx zzz`: directory `zzz`); System.CommandLine kept adding them to the option. `CommanderArgs.Normalize` moves those positionals in front of the option run. A child's environment value ends at its first NUL (the OS block is NUL-terminated), where .NET started a new variable. Node builds a regular expression from every key and value it rewrites, and V8 rejects one for a value of roughly 30 KB or more (`Invalid regular expression`); .NET has no such limit, so the sweep keeps its large values at 16 KB (accepted engine limit). A directory where a file is expected is `EISDIR` in Node and an access-denied message here (native wording).
88. **Path forms follow `path.resolve` / `path.basename`, and `ignore` rejects non-relative paths.** `path.resolve('.env/')` is `.../.env` (no trailing separator) and `path.basename('.env/')` is `.env`, so `-f .env/` reads the file and the keys-file comment still says `# .env`; `NodePath.Resolve` and `NodePath.Basename` replace `Path.GetFullPath` and `Path.GetFileName` at every site where upstream calls them, and on Windows `Fsx` accepts a trailing separator on a file path like libuv does. node-ignore throws for a path that is empty, starts with `./`, `../` or `/`, is `.` or `..`, or (Windows) starts with a drive letter: `prebuild <absolute directory>` fails with ``path should be a `path.relative()`d string, but got "<path>"`` (backslashes are separators on Windows only, and the message shows the path as given). fdir does not follow symbolic links: `ls` reports a link to a directory like a file and never enters it (so `.env` linked to a directory is listed as `.env`), and the scanned-directory count skips links. ELOOP and ENOENT wording stays native.
89. **Streams, exit codes and conventions.** Round 16 (piped stdin of every shape into children that read, ignore or close it, 5 MB of output, binary output, interleaved stdout and stderr, exit codes from -2 to 1000, child signals, and a reader that goes away) found no difference. Round 17 (both conventions crossed with eleven NODE_ENV and DOTENV_ENV states, commands and file sets) found one: `process.env.DOTENV_ENV || process.env.NODE_ENV || 'development'` skips an empty value, so `NODE_ENV=` means development (`Conventions`). An invalid convention is an uncaught error in both; only its stack trace text differs. Node takes about a minute to encrypt 3,000 keys (quadratic), so the sweep keeps its many-key fixture at 600.
90. **Environment variables.** Round 18 crosses every environment variable the CLI reads (and the colour, terminal, locale and time zone ones) with eight values and eight commands. Findings: any variable that STARTS with `DOTENV_PRIVATE_KEY` selects a key file (`DOTENV_PRIVATE_KEYS` derives the empty suffix, so the file is `.env.`; `substring` clamps where `[start..]` would throw, now fixed), and upper/lower casing is invariant (a Turkish locale must not change `i`). The trailing-dot file name `.env.` is the documented Windows difference. An invalid convention in `DOTENV_CONVENTION` is the uncaught error whose stack trace text differs.
91. **Unicode casing is JavaScript's, not .NET's.** `toUpperCase` / `toLowerCase` use the full Unicode mapping (`straße` is `STRASSE`, `ﬁ` is `FI`, `ı` is `I`, `İ` lowercases to `i̇`, a final capital sigma becomes `ς`); .NET's invariant casing is one-to-one and differs, which changed the derived key names (`DOTENV_PRIVATE_KEY_STRASSE`) and file names. `JsCase` applies Node's mapping (tables generated from Node by `scripts/gen-js-case-tables.js`; regenerate them when the pinned Node's Unicode version changes) at the sites where upstream derives names from user data. Composed and decomposed forms (`é` versus `e` + combining accent) stay distinct, as in Node, and locale or time zone never changes any output (round 19).
92. **`ext` subcommands, attached values on multi-letter flags, longer sequences.** Round 20 runs every option and option pair of the `ext` subcommands (they were skipped by the generated option round) and 250 longer seeded sequences with `native` backed by the per-run fake store (the real store is shared by every worker and made the sequences race). commander splits an attached value only from a single-letter flag: `-ef=x` and `-ik=A` are unknown options even though `-ef` and `-ik` exist, while `-fk=x` is `-f` with the value `k=x` (`CommanderArgs.Normalize` reports the first as `unknownShort` and rewrites the second). (b) On Unix every dot file is Hidden, and `EnumerationOptions` skips Hidden by default (the legacy overloads do not): `ls` listed nothing until `AttributesToSkip` was 0. (c) `os_platform` is `linux` (lowercase) for Armor. (d) An invalid `LANG` / `LC_ALL` terminates .NET at startup with `Argument_CultureNotSupported` where Node ignores it: the tool now sets `InvariantGlobalization`. (e) An fs error message names the path as given on Linux and macOS and the absolute path on Windows (`NodePath.ErrorPath`). (f) `git diff HEAD` leaves stderr inherited in `precommit.js` (a repository without commits prints git's `fatal:` line); the .NET call now does too. 94. **What the full sweep on Linux and macOS found (Unix-only behavior).** (a) A child killed by a signal has no exit code in Node, so dotenvx exits 1 and (except SIGINT/SIGTERM) logs `Command was killed with <SIG> (<description>): <command and args>`; .NET reports 128+n and cannot tell a kill from `exit 143`, so `ChildSignal` calls `waitid(P_PID, ..., WEXITED|WNOWAIT)` right after `Start()` to read the real status (Linux `WNOWAIT` 0x01000000, macOS 0x20; falls back to the exit code if libc is unreachable). (b) Node starts a child with `{...process.env, ...env}`, keeping the machine order with overrides in place; .NET `Environment` is a Hashtable in hash order, so `ExecuteCommand` refills `StartInfo.Environment` in C `environ` order (`/proc/self/environ` on Linux, `_NSGetEnviron` on macOS). (c) `ENOTDIR` (a file where a directory is needed) is raw in Node and is not mapped to a missing env file (only `ENOENT` and `EISDIR` are). (d) A dangling symlink is "not existing" for `fs.existsSync` but .NET says it exists, so `Fsx` resolves link targets; `set`/`encrypt` then build a new file and the final write throws a raw `ENOENT`. (e) fdir turns `\` into `/` in the crawl root on every platform, so `prebuild sub\deep` crawls `sub/deep` and reads `sub\deep/.env`. (f) `ls` sorts by UTF-16 code unit off Windows (case-insensitive on Windows). (g) Armor `system_uuid` on Linux comes only from `/sys/class/dmi/id/product_uuid`, never `/etc/machine-id`. (h) .NET `FileNotFoundException.FileName` is the full path: rethrow with the path as given. (i) A freshly exited .NET apphost gives `ETXTBSY` for about 70 ms: install fakes by copying to a `.tmp` and renaming over. (j) Parity children must never inherit stdin (a command that reads it hangs): always redirect and close it. (k) Node cuts a large stdout write to a pipe on macOS (accepted difference 10).
